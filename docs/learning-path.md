# 풀이 기록 기반 오늘의 학습 경로

코딩테스트 목록(`/codingtest/practice` 등)의 상단에서 언어·자가 선택 수준·목표를 선택한다.
로그인이 필요하며 `GET /api/learning-path`는 저장 결과만 조회하고 AI를 호출하지 않는다.
`POST /api/learning-path`의 본문은 `{language, level, goal, refresh}`다. 사용자 ID는 받지 않고 SecurityContext에서 결정한다.

- language: java / python / javascript / c / cplus
- level: PRACTICE / BASIC / INTERMEDIATE / EXPERT (추천 문제 난이도의 상한)
- goal: BASICS (기초 복습 우선) / PRACTICE (반복문 연습부터 시작)
- refresh: true면 같은 기록에서도 새 스냅샷 생성. false면 같은 지문(fingerprint)의 저장 결과 재사용.

## 추천 규칙 v1

최근 90일의 선택 언어 제출을 문제별로 묶어 최신 결과를 한 번만 반영한다.
선택 언어에서 전체 기간 중 한 번이라도 정답을 받은 문제는 후보에서 제외하며, 이를 숙련도 증명으로 해석하지 않는다.
문제에 여러 개념 태그가 있으면 각 개념의 근거에 같은 문제가 포함될 수 있다. 개념별 점수는 확률이나 정답률이 아니다.

미해결 문제별 점수:
- 최신 결과가 WRONG_ANSWER: 3점, 14일 이내면 추가 1점.
- 해당 문제의 공개 완료된 힌트 최고 단계: 1~3점 추가. 반복 조회/다른 시도의 같은 단계는 중복 합산하지 않는다.
- 정답 이력이 있는 문제: 실패·힌트 점수 0점.
- 컴파일/실행 오류·시간/메모리 초과만으로는 개념 점수를 올리지 않는다. 힌트 사용은 별도의 관측 근거다.

선택 언어를 식별할 수 없는 제출 전 힌트(`CodeHint.judgment=null`)는 제외한다.
힌트는 요청·생성 실패 횟수가 아닌 `code_hint`의 실제 공개 기록을 사용한다.
리뷰 문장, 강의 열람, 화면의 진도 표시를 숙련도/완료 기록으로 사용하지 않는다.

점수가 가장 높은 개념 중 현재 수준에서 미해결 문제 후보가 있는 개념을 선택한다.
동점이면 목표의 시작 개념, 이후 이름순으로 안정적으로 결정한다.
선수 개념 강의(직접 선수 하나) → 목표 강의 → 난이도/ID순 새 문제 → WRONG_ANSWER 미해결 재도전으로 후보를 구성한다.
기술적 오류만 있는 문제는 개념 부족으로 지칭하지 않고, 새 연습/오답 후보가 없을 때 재연습으로 제공한다.
AI는 3~5개 후보 ID를 선택한다. 선수/복습/연습/재도전 중 제공된 유형은 빠뜨릴 수 없고 순서도 지켜야 한다.
제목·링크·추천 근거는 서버 후보의 값을 사용하므로 모델이 임의로 URL이나 통계를 만들 수 없다.
후보가 부족하면 중복/가짜 콘텐츠로 채우지 않고 0~2단계도 허용하며 UI에 사유를 표시한다.

## 태그와 운영 적용

`backend/src/main/resources/learning/catalog.json`은 검토한 명시적 매핑이다.
현재 시드의 문제 1~15번(연산자·조건문·반복문·배열·문자열)만 태그를 적용한다. 16~17번과 미등록 운영 문제는 미분류다.
해시 선수 관계/일부 강의 매핑은 준비되어 있지만 태그된 해시 문제가 없으므로 해시 학습 경로를 임의로 만들지 않는다. 재귀는 아직 미지원이다.
문제는 ID **및 정확한 제목**, 강의는 언어/챕터/강의키 **및 정확한 라벨**이 맞아야 매핑한다.
본문이 비어 있는 강의는 제외한다. 현재 시드는 Java·Python 일부만 관련 강의가 준비되어 있고 C/C++의 관련 강의는 대부분 비어 있다. JavaScript는 명시적 개념 매핑이 아직 없다.
등록된 문제는 언어 공통이며, 언어는 제출 이력/강의 범위에 적용한다.

운영에서는 `learning.catalog=file:/absolute/path/catalog.json`으로 별도 매핑 파일을 지정할 수 있다.
새 문제/강의의 실제 내용을 검토한 뒤 ID/경로/제목을 등록하고 manifest.version을 증가시킨 뒤 재시작한다.
분류를 추측하거나 기존 data.sql/강의 본문을 일괄 수정하지 않는다. 데이터가 다른 운영 DB에서는 제목 불일치 항목을 제외한다.
현재 수준과 후보 수에 따른 정확한 지원 범위는 응답 notice/UI에 표시한다.

## 저장·갱신·실패 처리

새 `learning_plan` 테이블에 사용자, 프로필 키, 규칙 버전, 기준 시점, 생성 시점, 입력 스냅샷/근거, 후보, 확정 단계, fingerprint를 저장한다.
기존 테이블 변경은 없다. 개발 환경은 기존 ddl-auto=update로 생성한다. 운영 환경의 DDL은 `docs/learning-path-schema.sql`을 먼저 검토·적용한다.
히스토리는 새 행으로 보존한다. 새 제출·힌트 공개·강의/문제/매핑 변경은 지문을 바꾼다.
GET은 기존 경로와 stale 안내를 반환하며, 새 추천 요청 시 갱신한다. 이미 해결되거나 삭제/비공개/재분류된 콘텐츠는 저장 경로의 활성 링크에서 제외한다.

짧은 사용자 행 잠금 트랜잭션으로 PENDING을 선점하고 외부 AI 호출 중에는 트랜잭션을 유지하지 않는다.
동일 사용자/프로필의 생성 중 요청은 기존 상태를 반환한다. 180초가 지난 미완료 생성은 재시도할 수 있다.
Python은 기존 review/hint의 제한된 LangGraph 루프를 재사용한다(최대 모델 5회, 시간 예산 35초, 호출 타임아웃 20초).
도구는 `get_learning_summary`, `find_learning_candidates`, `submit_learning_path` 세 가지며 요청 범위 스냅샷만 조회한다.
사용자 토큰/ID 입력과 범용 데이터 조회는 허용하지 않는다. 강의 검색을 추가해 후보 밖의 강의를 끼워 넣지 않는다.
출력은 Python과 Spring에서 후보 ID·중복·개수·단계 순서를 모두 검증한다.
AI 키 누락/시간 초과/잘못된 응답이면 서버 규칙으로 유효한 경로를 저장한다(`source=RULES`).

추천 설명은 서버 근거를 보존하는 템플릿이다. AI는 후보의 선택·순서를 구성하며, 자유 서술로 취약점을 진단하지 않는다.

## 검증의 범위

LearningEngineTest: 규칙, 중복 실패, 해결 반영, 힌트, 언어/난이도, 미분류/빈 강의, 후보 검증.
LearningPlanServiceTest: 저장 JSON/재조회/기록 변경/새 추천/기본 경로/사용자 분리/생성 중/삭제 콘텐츠 (저장소 및 AI는 모의 객체).
LearningPlanControllerTest: 비로그인 거절 및 요청의 사용자 ID가 인증 사용자를 대체하지 못함 (standalone MockMvc).
Python test_learning_graph.py: 모의 모델의 도구 루프, 요청 범위, 후보 검증 및 서비스 인증.
실제 모델의 학습 경로 품질과 실제 MySQL/Elasticsearch/Claude 통합 검증은 위 모의 테스트로 보장하지 않는다.

기존 build.gradle은 test 태스크를 비활성화하므로 검증 시 다음 init 스크립트를 사용한다:

```groovy
allprojects { afterEvaluate { tasks.withType(Test).configureEach { enabled = true } } }
```

`gradle test -I /path/to/enable-tests.gradle`로 기존 테스트와 함께 실행할 수 있다.
